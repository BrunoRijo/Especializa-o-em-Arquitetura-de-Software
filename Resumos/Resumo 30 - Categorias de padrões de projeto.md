# Categorias de padrões de Projeto
>[!Note]
>Resumo 30 | Especialização em Arquitetura de Software por Bruno Rijo

Nesse resumo de hoje vou falar bem resumidamente, sobre as categorias de padrões de projetos que conhecemos e utilizamos hoje em dia.

Basicamente, Em 1994, um grupo de autores que ficou conhecido como de Gang of Four, lançou o livro “Padrões de Projeto: soluções reutilizáveis de software orientado a objetos”, onde foram catalogados 23 padrões divididos em três grupos, são eles:
 
1. De Criação
   
Utilizados para abstrair ou adiar o processo de criação dos objetos, ajudando a tornar o sistema independente, sem a necessidade de saber previamente como os seus objetivos são criados ou representados. Há uma existência de padrão de criação de classes com uso de heranças e de criação de objetos, delegando a instância para outro objeto.

2. De Estrutura
   
  Possuem um conceito totalmente oposto aos criacionais.Nessa categoria é extremamente importante saber como os objetos e classes são criados, porque somente assim é que podemos escalar o código estruturalmente. Os padrões estruturais DE CLASSE sempre utilizam o conceito de herança dentro do código, na interface ou na implementação. Já os padrões estruturais DE OBJETOS, nunca utilizam a herança ou na interface, isso porque utilizam os objetos para ter novas funcionalidades.

3. De comportamento. 

  Se concentram nos algoritmos e nas atribuições de responsabilidades entre os objetos, não descrevem somente os padrões de classe e objetos mas também padrões de comunicação. Os de classe utilizam a herança par distribuir o comportamento entre as classes, enquanto os de objetos vão utilizar a composição desses objetos em contrapartida a herança, alguns padroes vão descrever como os objetos cooperam para a execução de uma tarefa que não poderia ser executada por um objeto sozinho.
